# Data setup

NS-TQA uses four **public** PHM datasets. They are not redistributed here — download each from
its source and unpack it under `data/raw/` exactly as shown below, so the dataset adapters in
`src/benchmark/` find the files. The processed health-indicator caches (`data/processed/*.pkl`)
are generated by the code on first use and are git-ignored.

> Links are the commonly used sources at the time of writing; some may move or require (free)
> registration. If a path changes, search for the dataset name — all four are widely mirrored.

## Datasets and download links

### 1. NASA C-MAPSS — Turbofan Engine Degradation Simulation (FD001–FD004)
Engine QA, shift factorization (FD001→FD002/3/4), RUL-grounded questions, conformal confidence.
- NASA Prognostics Center of Excellence (PCoE) data repository:
  <https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/>
  (look for *"Turbofan Engine Degradation Simulation Data Set"*).
- Also widely mirrored on Kaggle (search *"CMAPSS"* / *"NASA Turbofan Jet Engine"*).

### 2. XJTU-SY Bearing Datasets
Bearing QA, cross-load shift (35 Hz/12 kN → 37.5 Hz/11 kN, 40 Hz/10 kN), cross-rig transfer.
- Official page: <https://biaowang.tech/xjtu-sy-bearing-datasets/>
- (Wang, Lei et al., XJTU.) GitHub mirrors exist — search *"XJTU-SY bearing datasets"*.

### 3. FEMTO / PRONOSTIA — IEEE PHM 2012 Prognostic Challenge
Cross-rig transfer (source rig).
- FEMTO-ST Institute dataset; commonly mirrored at
  <https://github.com/wkzs111/phm-ieee-2012-data-challenge-dataset>
- Also hosted on the NASA PCoE repository as *"FEMTO Bearing Data Set"*.

### 4. NASA IMS Bearing Data Set (University of Cincinnati)
Cross-rig transfer (target rig).
- NASA PCoE data repository, *"Bearing Data Set"* (IMS):
  <https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/>

## Expected directory layout

```
data/raw/
├── CMAPSS/
│   ├── train_FD001.txt  train_FD002.txt  train_FD003.txt  train_FD004.txt
│   ├── test_FD001.txt   test_FD002.txt   test_FD003.txt   test_FD004.txt
│   └── RUL_FD001.txt    RUL_FD002.txt    RUL_FD003.txt    RUL_FD004.txt
│
├── XJTU-SY_Bearing_Datasets/
│   └── Data/
│       └── XJTU-SY_Bearing_Datasets/
│           ├── 35Hz12kN/     ( Bearing1_1/ … each folder holds the per-record CSV files )
│           ├── 37.5Hz11kN/    ( Bearing2_1/ … )
│           └── 40Hz10kN/      ( Bearing3_1/ … )
│
├── IEEE_PRONOSTIA_PHM/
│   └── dataset/
│       ├── Learning_set/     ( Bearing1_1/ … acc_*.csv )
│       └── Test_set/         ( … )
│
└── NASA_IMS_Bearings/
    ├── 1st_test/             ( raw ASCII vibration records )
    ├── 2nd_test/
    └── 3rd_test/
```

The exact folder names above (`CMAPSS`, `XJTU-SY_Bearing_Datasets/Data/…`, `IEEE_PRONOSTIA_PHM/dataset`,
`NASA_IMS_Bearings`, and the XJTU operating-condition folders `35Hz12kN` etc.) are the roots the
configs in `configs/` point to — keep them as shown, or edit the corresponding `*_root` keys in the
config YAMLs.

## After downloading

The first run of a real-data experiment builds and caches the health-indicator features under
`data/processed/`. Subsequent runs reuse the cache. Only the synthetic-necessity experiments
(`scripts/10`, `11`) need no downloaded data.
